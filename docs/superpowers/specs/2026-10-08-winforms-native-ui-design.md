# Khitun Geo: перенос интерфейса на WinForms Native

Статус: дизайн к согласованию. Рабочий код приложения пока не меняется.

## Цель

Перейти от HTML-интерфейса внутри WebView2 к нативному WinForms-интерфейсу,
сохранив офлайн-работу, точность координат, текущие сценарии импорта/экспорта
и возможность дальнейшей оптимизации RAM.

Главная причина переноса: WebView2 добавляет браузерный слой, который увеличивает
память, размер установки и усложняет управление визуализацией. WinForms Native
должен стать строгим инженерным интерфейсом: плотным, понятным, быстрым и без
лишней декоративности.

## Что есть сейчас

- Windows-приложение уже собрано на WinForms и .NET 8.
- Основной экран открыт через `Microsoft.Web.WebView2`.
- UI, таблица, визуализация и часть бизнес-логики находятся в `wwwroot`.
- Координатные формулы сейчас находятся в JavaScript внутри `index.html`.
- DWG/DXF импорт и часть Windows-интеграции уже находятся в C#.

Из этого следует важное ограничение: убрать WebView2 полностью нельзя одним
маленьким изменением. Сначала нужно разделить браузерный UI, координатные
расчёты, хранение данных и Windows-интеграцию.

## Границы первого этапа

Первый этап не меняет математические формулы координат и не переносит ядро на
Rust/C++. Цель первого этапа — подготовить нативный интерфейс и безопасные
границы между модулями.

В первый этап входит:

- нативная структура главного окна WinForms;
- левая компактная панель навигации;
- верхняя строка преобразования СК;
- таблица точек на `DataGridView`;
- статусная строка с количеством точек, ошибками и памятью;
- переключение светлой и тёмной темы;
- заготовка нативной области визуализации;
- единая модель точки в C#;
- адаптер между текущими данными и новым UI.

В первый этап не входит:

- переписывание координатных формул;
- изменение параметров СК;
- выпуск установщика;
- загрузка на GitHub;
- удаление WebView2 из проекта до готовой замены расчётов, паспорта и PDF.

## Интерфейс

Главное окно:

- слева узкая панель с разделами: импорт, точки, высота, экспорт, сервис;
- сверху только рабочая строка: исходная СК, реверс, целевая СК,
  преобразовать;
- центр делится на таблицу точек и визуализацию;
- снизу статусная строка: состояние, количество точек, текущая пара СК, RAM,
  ошибки.

Интерфейс должен быть похож на инженерный инструмент, а не на сайт:

- плотная таблица;
- минимальные карточки;
- без больших пустых блоков;
- без тяжёлых эффектов;
- все частые действия видны сразу;
- редкие действия уходят в сервисные окна.

## Анимации

Анимации разрешены, но только лёгкие:

- раскрытие и сжатие левой панели;
- hover и нажатия кнопок;
- мягкое появление уведомлений;
- подсветка ошибок в таблице;
- плавное переключение темы;
- прогресс импорта DWG/DXF.

Анимации запрещены там, где они могут создавать микрофризы:

- ввод X/Y/Z;
- массовая вставка точек;
- импорт большого DWG/DXF;
- фоновая визуализация;
- перерисовка больших наборов объектов.

Нужна настройка "уменьшить анимации".

## Визуализация

Нативная визуализация должна работать как отдельный компонент WinForms:

- полностью отключаться при скрытии;
- не держать таймеры и фоновые задачи, когда скрыта;
- ограничивать камеру границами точек или DWG;
- не готовить данные для пустой области за границами;
- отсекать объекты вне видимой области;
- не обновляться на каждый ввод символа в таблице.

На первом этапе достаточно подготовить компонент и границы данных. Полная
оптимизация DWG-визуализации выполняется отдельной задачей после замера RAM.

## Таблица

Таблица должна заменить HTML-таблицу:

- редактирование X/Y/высоты/описания;
- вставка `Ctrl+V` из Excel, CSV и текста;
- выделение строк и столбцов через `Ctrl` и `Shift`;
- очистка выбранных значений без удаления столбцов;
- отмена через `Ctrl+Z`;
- минимальные перерисовки при вводе;
- валидация после завершения редактирования, а не на каждый символ.

Это должно убрать микрофризы при ручном изменении X/Y/Z.

## Высота

Добавляется отдельный нативный инструмент расчёта высоты для всех точек сразу:

- абсолютная отметка минус глубина;
- абсолютная отметка плюс поправка;
- пример: `86.65 - 12 = 74.65`;
- поддержка отрицательных значений;
- применение только ко всем точкам;
- отмена через `Ctrl+Z`.

## Координатные расчёты

Так как ядро не переносим на Rust/C++, координатные формулы не переписываются
вслепую. Нужен безопасный промежуточный путь:

1. Вынести координатные функции из HTML в отдельный модуль.
2. Сохранить существующие численные тесты.
3. Добавить регрессионные контрольные точки для основных СК.
4. Подключить расчёты к WinForms через явный адаптер.
5. Только после совпадения результатов переключать UI на новый вызов.

Если выбирается C#-реализация формул, это считается переносом математической
логики и требует фиксированного регрессионного набора. Если выбирается запуск
выделенного JS-модуля без WebView2, формулы всё равно проверяются тем же
набором, потому что меняется окружение выполнения.

## PDF и паспорт

Сейчас PDF-паспорт зависит от WebView2. Для полного удаления WebView2 нужно
заменить этот участок:

- либо нативная генерация PDF;
- либо HTML-файл без встроенного WebView2, открываемый внешним просмотрщиком;
- либо временно оставить PDF через WebView2 до отдельной замены.

На первом этапе PDF не трогаем, чтобы не смешивать перенос интерфейса и экспорт.

## Проверки

Минимальная проверка первого этапа:

- приложение запускается;
- таблица отображает и редактирует точки;
- ввод X/Y/высоты не вызывает заметных микрофризов;
- `Ctrl+V`, `Ctrl+Z`, выделение строк/столбцов работают;
- переключение темы не ломает размеры;
- скрытие визуализации освобождает рабочую область;
- координатные тесты проходят без изменения формул;
- DWG/DXF импорт не ухудшен.

Для функций координат, импорта/экспорта и DWG экономия проверок не применяется.

## Риски

- Полное удаление WebView2 упирается не только в UI, но и в расчёты, паспорт и
  PDF.
- WinForms требует аккуратного ручного дизайна, иначе интерфейс будет выглядеть
  старым.
- `DataGridView` нужно настроить на большие наборы точек, иначе микрофризы
  останутся.
- Нельзя одновременно переносить интерфейс, менять формулы СК и оптимизировать
  DWG: это создаст слишком большой риск регрессий.

## Рекомендуемый порядок

1. Подготовить C# модели точек, состояния приложения и команд.
2. Сделать нативный главный экран по выбранному концепту.
3. Перенести таблицу точек и базовое редактирование.
4. Добавить историю `Ctrl+Z` для таблицы.
5. Добавить нативные темы и лёгкие анимации.
6. Подключить текущие импорт/экспорт команды.
7. Отдельно решить безопасный путь для координатного модуля без WebView2.
8. После проверок убрать WebView2-зависимость из основного экрана.
